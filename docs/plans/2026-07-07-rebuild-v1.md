# 「见微」AI for Science 大陆情报系统 v1.0 重构实施计划

> **For agentic workers:** 本计划由本会话 inline 执行（executing-plans 模式），任务用 checkbox 追踪。
>
> **产品名**：见微（取"见微知著"——系统看见微弱信号，你得到大局判断）

**Goal:** 把 v0.1 手工录入看板重构为商业级个人情报产品：自动采集中国 AI4S/生物医药政策与企业动态 → DeepSeek 逐条深读并按用户决策维度打分 → 每日晨报 + 个性化情报流 + 引用式对话 + 每周自进化，移动优先、桌面自适应。

**Architecture:** 单体 FastAPI（分层包）+ SQLite WAL/FTS5 + 进程内 APScheduler + DeepSeek（v4-flash 批量分析 / v4-pro 对话晨报）。无外部服务依赖（明确不用 Supabase：单用户、本地读写 <1ms、单文件备份）。前端 Vanilla ES modules 无构建，自适应响应式双形态（手机=底部标签+抽屉；桌面=侧边栏+双栏 master-detail）。

**Tech Stack:** FastAPI · SQLAlchemy 2.0 (sync) · SQLite FTS5 + jieba · httpx · feedparser · BeautifulSoup/lxml · APScheduler · pydantic-settings · Vanilla JS/CSS

## 0. 产品设计（为什么这么做）

### 0.1 用户与痛点

Oliver 需要为三个现实决策持续获取大陆情报：① AstraZeneca 北京（亦庄）职业机会；② TrustPathBot 市场定位；③ UK vs 大陆定居。痛点不是"没有信息"，而是：信息散落在十几个政府网站/媒体里、绝大部分与己无关、读不过来、判断不了"这条对我意味着什么"。

### 0.2 产品形态：不是资讯聚合器，是「私人情报分析师」

核心差异化 = **画像驱动的逐条深读**。每条情报入库后，DeepSeek 拿着你的兴趣画像和决策维度逐条回答："这条讲什么？对 Oliver 的哪个决策有影响？多重要？该做什么？"——这是人类分析师的工作方式，也是大模型理解力的正确用法。

五个机制闭环：

1. **兴趣画像（Profile-as-Prompt）**：一段可编辑的自然语言画像 + 5 个决策维度（带权重），注入每次分析。
2. **AI 分析师流水线**：采集 → 关键词门控 → DeepSeek 结构化分析（摘要/分类/实体/各维度评分+理由/行动提示/申报截止日）→ 加权综合分 → 🔴必读/🟠关注/🔵扫一眼/⚪归档 分级。
3. **每日晨报**（07:30 北京时间）：v4-pro 把 24h 内高分条目写成 3 分钟简报：头条+对你的影响、政策雷达、企业动态、弱信号、临期提醒（申报截止倒计时）。
4. **反馈进化**：👍有用/👎无关/⭐收藏/🚩跟进 四键反馈；每周日晚 DeepSeek 复盘一周反馈 → 生成进化报告 + 修改建议（加关键词/调权重/加实体/调源），**用户一键采纳制**（透明，不偷偷改画像）。
5. **对话（问情报）**：v4-pro + FTS 检索增强，回答带 [n] 引用链接到具体条目，画像常驻上下文。

### 0.3 决策维度种子（继承 v0.1 的多维评分思想并泛化）

| id | 名称 | 权重 | 判据描述（给 LLM 的） |
|---|---|---|---|
| az_career | AZ北京·亦庄机会 | 0.30 | AstraZeneca 中国动向、亦庄/经开区生物医药园区政策、外企在华研发投入信号 |
| trustpathbot | TrustPathBot 市场 | 0.25 | AI 可信/合规/监管科技需求、医药数字化合规、AI 治理政策落地 |
| talent_funding | 人才与资金 | 0.20 | 人才计划（海聚等）、基金/课题申报窗口、补贴、有明确截止日期的机会 |
| settle_decision | 定居决策 | 0.15 | 宏观政策环境、外企营商环境、行业景气度、京津冀生活配套政策 |
| industry | AI4S 行业大盘 | 0.10 | AI 制药/大模型/算力/融资并购/头部公司（晶泰、英矽、深势、百图…）动态 |

`final_score = 0.55×Σ(wᵢ·lensᵢ)/Σw + 0.25×importance + 0.20×source_authority`；tier: ≥75🔴 ≥60🟠 ≥45🔵 else ⚪。

## 1. 架构设计（地基）

### 1.1 决策与理由

- **单体分层，不搞微服务**：单用户、日均 <300 新条目、峰值 QPS 个位数。商业级体现在可靠性工程：单源故障隔离+健康度监控、LLM 故障降级（条目先入库标 pending，稍后补分析）、结构化 JSONL 日志、schema 版本化迁移、用量记账。
- **SQLite WAL + FTS5，不用 Supabase**：本地零网络跳；FTS5 + jieba 分词解决中文全文检索；单文件备份。唯一约束：uvicorn 单 worker（调度器进程内），已满足。
- **调度进程内（APScheduler BackgroundScheduler）**：省掉独立 worker/队列。时区显式 `Asia/Shanghai`（服务器是 UTC）。
- **SSE 流式聊天**：FastAPI StreamingResponse + 响应头 `X-Accel-Buffering: no`（免改 nginx 配置即可穿透反代缓冲）。
- **认证**：nginx basic-auth（已有）作为唯一门禁；应用层不再造轮子。key 只存 `.env`（gitignored）。

## 2. 情报检索设计（信息面）

### 2.1 分层源注册表（已实测可达性，2026-07-07 自 kumo VPS）

| Tier | 源 | 方式 | 频率 | 实测 |

| 1 | 北京科创中心·经开区动态 ncsti.gov.cn | HTML | 2h | 200 ✅ |

| 2 国家 | 国务院最新政策 gov.cn/zhengce/zuixin | HTML | 4h | 200 ✅ |
| 2 | 科技部通知 most.gov.cn/tztg | HTML | 4h | 200 ✅ |
| 2 | 工信部 miit.gov.cn | HTML | 4h | 200 ✅ |

| 3 媒体 | 36氪 RSS | RSS+门控 | 2h | 200 ✅ |
| 3 | 量子位 RSS qbitai.com/feed | RSS+门控 | 2h | 200 ✅ |
| 3 | 科技日报 stdaily.com | HTML+门控 | 4h | 200 ✅ |
| — 禁用待通道 | NMPA(412反爬)、卫健委(不可达)、动脉网(不可达)、机器之心(RSS收费) | — | — | 注册表中 enabled:false 留档 |

设计原则：**声明式**（加源=改 YAML，不写代码）；**故障隔离**（单源连败→health=degraded/down，UI 可见，不影响其他源）；**门控**（媒体源先过关键词门控再进 LLM，政府源低量全分析）；**条件请求**（ETag/Last-Modified 省流）。

### 2.2 去重与聚合

URL 规范化(去 utm/锚点)→sha1 为 uid 硬去重；标题 simhash 海明距离 ≤6 视为同事件软去重（保权威源，media 重复标记 cluster）。

### 2.3 检索（供搜索框与 RAG 共用）

查询 → jieba 分词 → FTS5 MATCH（title/content/summary 三列，title 权重↑）→ BM25 × 新鲜度衰减 → top-k。RAG 再截断拼 prompt，引用编号回链条目。

## 3. UI/UX 设计（自适应双形态）

**一套代码通吃手机+桌面**（业界主流：Linear/Notion 模式），不做 UA 跳转双站：

- **手机 <768px**：底部 5 标签（今日/情报/问/洞察/我的）+ 全屏单栏 + 详情=底部抽屉（拖拽关闭）+ 反馈四键贴底 + 安全区适配 + 44px 触区。
- **桌面 ≥1024px**：左侧边栏导航 + 情报页=「列表 420px + 右侧详情面板」双栏（邮件客户端式）+ 悬停态 + 今日页双栏仪表布局 + 对话居中限宽。
- **768–1023 平板**：单栏加宽 + 侧边栏图标态。
- 设计语言：「指挥中心」暗色默认（深墨 #0B0E14 底 + 琥珀强调=🔴级 + 青色链接），浅色随系统；系统中文字体栈（PingFang SC/HarmonyOS Sans/Noto Sans CJK），数字 tabular-nums；骨架屏；PWA manifest（HTTPS 后可安装）。
- 实现：CSS 自定义属性 + Grid + 3 断点；JS `matchMedia` 决定详情呈现（抽屉 vs 右栏），组件 API 统一 `openItem(id)`。
